## GTNH 开服到底吃什么资源

答案分三层：内存决定能不能稳定跑起来，单核决定 TPS 稳不稳，磁盘决定你这个存档能活多久。三者里最容易被低估的是内存。

### 内存：能启动和能玩是两回事

GTNH 官方推荐的客户端启动方式是 MC 1.7.10 加 Forge 1614，把整合包压缩包里的文件直接拖进 `.minecraft`；用 MMC 打包版的话支持 Java 17 到 21。服务端是同一套环境，主机必须允许你选 Java 版本，只给 Java 8 的老面板会出问题。

近 300 个模组同时加载，服务端光是把世界和配方表读进内存就要占掉一大块。公开的开服教程给同类大型整合包的建议是 4核10G 起步、不低于 4核8G，GTNH 的模组体量和它们同级，但它的存档是持续增长的，所以 10G 是起点而不是上限。

### 单核：1.7.10 的服务端仍然靠一个线程

Minecraft 的 Java 服务端主逻辑跑在主线程上，你给多少核它都只用一个。GTNH 的机器、管道、物流在后期是成千上万个小方块实体，每次 tick 都要算一遍。核数多解决不了 TPS，主频高才行。

这也是为什么同一档内存下，Ryzen 7950X、9950X 和 i9-14900KF 卖得比 E5 贵。E5 2666V3 跑个两三人、还停在蒸汽时代的存档没问题，等朋友把厂区铺到上千个区块，你就会开始看见服务器每秒钟的 tick 时间往上飘。

### 磁盘和存档：这是长期工程

GTNH 官方社区的说法是，没有上千个区块的厂区和无数高度自动化的产线，很难体会到这个包真正的乐趣。任务线从石器、蒸汽一路排到 LV 32、MV 128、HV 512、EV 2048、IV 8192、LuV 32768、ZPM 131072、UV 524288、UHV 2097152，每个阶段都是一次产能重建。

一个存档跑一年以上、厂区持续扩张，地图文件和区块数据会一直变大。选主机时把磁盘余量和备份能力算进去，别等存档写到一半没地方放。

## 开服前必须确认的五个坑

**别把版本号写死。** 中文社区资源页上标的是 2.7.0，但那个页面自己注明了部分内容已过期、一切以 GTNH 中文 Wiki 为准；2026 年 4 月的社区实况视频里，实际在跑的是 2.8.4。开服前先去官网下载页和中文 Wiki 对一遍当前版本，服务端和客户端必须完全一致。

**客户端要 Forge 1614。** 这不是可选项。玩家装的是 1.7.10 + Forge 1614 环境，服务端少一个版本号都连不上。

**用 Linux，别用 Windows 开服。** Windows 系统自身就吃掉一部分内存和 CPU，同样的配置在 Linux 上能多带几个人。雨云面板服默认就是 Linux 环境，正好省掉这一步。

**端口要改成面板给的映射端口。** 服务端压缩包解压后，`server.properties` 里的 `server-port=25565` 要改成控制台显示的那个端口号，不改连不上。同一批要看的还有 `online-mode`（正版验证）、`view-distance` 和 `simulation-distance`，后两个直接决定服务端每 tick 要处理多少区块。

**存档会越跑越重。** GTNH 的生存设定本身就拉长在线时间：夜晚全黑，没夜视药水什么都看不见；怪物死亡会爆炸；开局要靠捡花园、攒泥土换苹果。玩家在线时长高、挂机多，服务端是长时间高负载运行，选主机时按"能连续跑几个月"的标准挑，不是按"能开起来"挑。

## 常见问题

**GTNH 服务器最少要多少内存？**
8G 是能跑起来的下限，10G 是能稳住的下限。人一多或者进了 EV 之后，12G 更安全。

**能不能自己加装别的 Mod？**
能。服务端加什么，所有玩家的客户端就得装同样的，版本号也要对上。加之前先在本地单人存档里跑一遍，确认不崩再上传。

**TPS 掉了怎么办？**
先看单核占用是不是满了，满了只能换高频机型。没满就往两个方向查：视距和模拟距离调小，以及找出谁在挂大量实体。后期常见的元凶是没做限流的自动化产线和堆在一起的机器。

**单人存档能不能搬到服务器？**
可以。把本地 `.minecraft/saves` 里对应的存档文件夹整个上传到服务端根目录，文件夹名保持 `world`，启动后玩家数据、地图、进度都在。

**年付和月付差多少？**
雨云的年付是 7 折。以 4核10G 那一档算，月付和年付折算下来一个月差二三十元，跑满一年差几百元。GTNH 这种要长期挂着的服，年付更合适。
